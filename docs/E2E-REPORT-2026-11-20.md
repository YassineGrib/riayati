# End-to-end test report, 2026-11-20

Environment: Android emulator, debug build against the local Laravel server (`127.0.0.1:8765` through `adb reverse`), Filament admin in the in-app browser. Test accounts come from `database/seeders/E2eAccountsSeeder.php` (local only, never run in production).

## Worked
- Login as father and mother; the father's invite code linked the mother (the app shows "مرتبط بالأب").
- "تخطي الآن" on the link screen; Home opens, calendar card asks to link.
- Home: SOS card and the two shortcut cards.
- Library: list, type chips, detail. Centers: list, kind chips, wilaya filter, detail, call and copy buttons.
- New report with a photo (compressed to 143 KB), sent as RIA-2026-0143, listed under "بلاغاتي", detail screen, PDF opens (Arabic text correct, the photo on page 2).
- Calendar: the mother proposed a visit (25 Nov, 10:00-12:00), the father saw it and accepted; status "تم القبول".
- Admin: the report appears with reporter, attachment tile and timeline; "تمت المراجعة" asks for confirmation and works; the activity log recorded `report.reviewed`; visits list shows the accepted visit.

## Bugs found (to fix)
1. Report summary screen (after sending): "العودة للرئيسية" does nothing (system back works); the PDF card is not tappable.
2. Home still shows "no reports" right after sending one; it refreshes only after restarting the app.
3. Reports list says "بدون مرفقات" for a report that has one attachment (detail says one).
4. Digits mix in right-to-left text: date field of the new report, summary screen, Home card (`٢٠٢٦ · ١٠:٣٤` garbled); attachment name and size show as `jpg.53` and `KB 143`.
5. Summary screen shows 10:34 while the list, detail, PDF and admin show 11:34 (time zone).
6. Visit form: date and time are plain text (YYYY-MM-DD, HH:mm) although the icons suggest pickers; `1000` is rejected, which is correct but unfriendly.
7. Center detail: phone and working hours order is slightly off in the RTL layout; address "غير محدد" for placeholder data.
8. Skipping the link is forgotten when the app is fully closed (shown again next start).

## Fixes (same day)
1. Summary screen is now a router route: "العودة للرئيسية" works; the PDF card opens the PDF (spinner, error text). Checked on the emulator.
2. Home and the reports list reload as soon as a report is sent (`reportsRevisionProvider`). Checked on the emulator: two new reports appeared at once.
3. API bug: the reports list always returned `attachments_count: 0` (array `+` kept the first value); fixed with `array_merge`, test added (135 backend tests).
4. One shared formatter (`lib/core/format.dart`): date and time are separate isolated runs, Latin digits, same everywhere; file names and sizes isolated.
5. Times are converted to the device time zone everywhere (the summary used to show UTC).
6. Visit form: typing digits formats them (`1000` becomes `10:00`, `20261125` becomes `2026-11-25`); the calendar and clock icons already open pickers.
7. Skipping the link is remembered across restarts and cleared on sign-out.
8. Center detail digits: not changed (placeholder data only; recheck with real data).

## Second round (verified on the emulator)
- Notifications: the mother sees "وافق الطرف الآخر، أكّد الزيارة" and "تمت مراجعة بلاغك"; the bell shows a red dot.
- Visit detail: timeline correct; "تأكيد الزيارة" turns the visit to "مؤكدة".
- Profile: phone, wilaya (selector with search) and children count save and show; wrong current password gets "كلمة المرور الحالية غير صحيحة"; the correct one changes it.
- Dark mode: Home, library, reports look correct.
- Library search works; a content item created in the admin form (published) appeared in the app.
- Fixed: Arabic-Indic digits in Home, notifications and library dates (now one Latin-digit format), "1 مرفقات" wording (`attachmentsLabel`), and the library banner that claimed the content was "approved under Algerian law" (it is placeholder text) now says it is introductory guidance.

## Still open
- Forgot-password flow (needs a mail driver), declining a visit, and a real phone check are covered by automated tests only.
- Release APK: needs the production API address (HTTPS, because release builds block plain HTTP) passed as `--dart-define=API_URL=...`; the default points to the emulator on port 8000.
- Release builds are signed with the debug key; a real signing key is needed before the Play Store.

## Not verified (first round list)

- Notifications screen, change password, edit profile save, forgot password, decline and confirm visit, dark mode on the device, content search, SOS card action.
